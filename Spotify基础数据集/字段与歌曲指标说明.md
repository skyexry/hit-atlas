# Spotify 热门歌曲项目 · 基础字段与歌曲指标

当前 CSV 记录哪些歌曲上榜。以下歌曲特征是待确认的设计，示例数值仅用于解释公式。第一版优先做原语歌词主题、情绪用词和重复行，声音特征与乐评按实际覆盖增补。

## 1. 已有字段

| CSV | 每行代表什么 | 实际字段 |
|---|---|---|
| 榜单明细.csv | 一个市场某年榜单中的一个位置 | year, market, position, track_title, artist_credit, analysis_set, record_status, market_scope, chart_id, spotify_track_id, id_provenance, source_type, source_url, observed_weekly_top200_streams, window_start, window_end |
| 全球年度趋势Top50_2017-2026.csv | 上表中一个全球榜位置，每年 50 首 | 与榜单明细相同。此表是筛选视图，合并统计时使用其中一份 |
| 地区同期Top50_2024-2026.csv | 一个市场、一个同期累计榜的位置 | year, market, position, track_title, artist_credit, observed_daily_chart_streams, chart_entries, window_start, window_end, observed_days, source_url, in_three_year_panel |
| 地区年份入口.csv | 一个可选的市场、年份和榜单口径 | market, market_zh, year, chart_type, chart_label, source_type, track_count, position_min, position_max, data_file, window_start, window_end, in_three_year_comparison |
| 地区日榜覆盖核验.csv | 一个市场某年的档案覆盖情况 | year, market, expected_days, observed_days, min_daily_entries, max_daily_entries, days_with_rank_gaps, duplicate_positions, complete, in_three_year_panel |
| 榜单来源.csv | 某张榜单的一项来源 | chart_id, year, market, source_type, source_title, source_version, source_url, supporting_url, documented_positions, detail_rows, note |

`year` 是上榜年，`market` 是听众市场，`position` 的含义随榜单口径而定。地区同期榜按每年 1 月 1 日至 11 月 12 日的日榜在榜播放量累计排序。`chart_entries` 是该曲名与署名组合的上榜记录条数，`observed_days` 是整个市场的观测天数。全球 2026 使用 1 月 2 日至 11 月 12 日的 45 个完整周榜。历史歌单保留来源曲序，缺少播放数的位置留空。

## 2. 给榜单接上歌曲特征

| 建议表 | 最少字段 | 用途 |
|---|---|---|
| chart_entries | year, market, chart_type, position, song_id | 每个榜位保留一行。2025 年同一市场可以同时有年度歌单和同期累计榜，关联时带上 chart_type |
| songs | song_id, title, artist_credit, recording_version, spotify_track_id, duration_ms, match_status | song_id 由项目分配，粒度为可辨认的录音版本。用曲名、艺人检索，辅以专辑、时长和版本说明确认同一录音。现场版、翻唱、混音和不同语言录音分别核验 |
| lyrics | song_id, lyrics_ref, lyrics_source_url, lyrics_status, text_hash, primary_language, language_line_counts, language_status | lyrics_ref 指向允许分析的原语文本。保留换行、重复演唱和原有段落标签。记录完整、片段、来源缺失或已确认纯器乐等状态。跨市场相同录音共用特征 |
| lyric_features | song_id, method_version, topic_id, topic_label, embedding_ref, emotion_counts, n_content_words, n_lexicon_hits, repeat_line_ratio | 保存离线计算结果、计数与版本。前端可只读取标签、得分、二维坐标和近邻 ID |
| audio_features、reviews（扩展） | song_id, duration_ms, tempo_bpm, energy, danceability, audio_valence, audio_source, audio_status；另存 review_id, review_url, review_scope, arrangement_note | 声音值对应具体录音。乐评按单曲、专辑中明确谈及本曲、专辑背景标记对象层级 |

用 CSV 加稳定主键即可开始。若做歌手入口，另建 song_artists(song_id, artist_id, credit_order)，将合作曲关联到各署名艺人。SQLite 可用于整理；可视化读导出的 CSV 或 JSON。

歌词候选可以在 LRCLIB 按曲名、艺人、专辑和时长查询。有同步歌词时去除时间戳并保留实际行序。记录文本来源、录音匹配和使用范围。Zenodo 的 LFM2b 已发布数据只纳入英文歌词，适合对重叠英文曲目的指标进行方法对照。[LRCLIB 文档](https://lrclib.net/docs) · [LFM2b 数据说明](https://zenodo.org/records/7740045)

## 3. 指标计算

**主题与语义近邻。** 采用已有提案的 sentence-transformers/paraphrase-multilingual-mpnet-base-v2。每首歌取原语唱词，删除时间戳、署名和段落标签。对主题分析只保留首次出现的完全相同段落。按段分块，长段先按行、再按模型 tokenizer 拆分，每块含特殊符号最多 128 个 token。使用模型的 mean pooling 产生 768 维向量，每块先做 L2 归一化，按有效 token 数加权平均，再对全曲向量做 L2 归一化。两个全曲向量的点积即余弦相似度，用它计算相似歌曲。[模型卡](https://huggingface.co/sentence-transformers/paraphrase-multilingual-mpnet-base-v2)

所有年份和地区共用一个主题模型。每个已确认的歌曲版本只入模一次。在全曲向量上尝试 5–10 类 K-means，固定随机种子、模型 revision、预处理和聚类参数。两人阅读每类距中心最近的曲目和随机样本并命名。结合轮廓系数、重跑稳定性、跨语言抽查和标签可解释性选择类别数。难以解释的标签记为“混合／待解释”。主表保存 topic_id、topic_label；可追加与主题中心的余弦相似度，字段名明确为相似度。可选的 embed_x、embed_y 来自一次固定的 UMAP 投影，供浏览；统计与近邻计算使用原向量。建议默认使用原始向量，把提案中的按语言中心化作为对照实验，检查其是否同时移除了有意义的题材差异。

**情绪用词。** 使用 NRC Emotion Lexicon 的八类关联及正负词标注。对完整原语歌词按语种分词、提取词元和词性，保留名词、动词、形容词、副词及其实际重复次数。令 N 为有效实词总词次，C_e 为命中某类的词次，H 为词典内存在对应词条的实词词次。每个词次在同一类别只计一次，跨类别可分别计数。保留词典版本、语言文件、分词器版本及各类别原始计数。[NRC EmoLex 官方说明](https://saifmohammad.com/WebPages/NRC-Emotion-Lexicon.htm)

| 字段 | 计算 | 可回答的问题 |
|---|---|---|
| joy_rate, sadness_rate, anger_rate, fear_rate, disgust_rate, surprise_rate, trust_rate, anticipation_rate | 各自为 100 × C_e / N | 每百实词中有几次与某类情绪相关的用词。八项可以重叠 |
| pos_rate, neg_rate, tone_balance | 前两项分别为 100 × 正面或负面词次 / N。tone_balance = pos_rate − neg_rate | 每百实词中正面相关词比负面相关词多几次 |
| lex_coverage | H / N | 词典对该语种这首歌的覆盖。N 或 H 为零时情绪值留空。有覆盖且类别命中为零才记 0 |
| repeat_line_ratio | 1 − 不同规范化歌词行数 / 全部有效演唱行数 | 出现过的整行再次出现，占全部演唱行的比例。删除时间戳、统一空白及大小写，保留实际唱出的重复 |
| chorus_line_share（可选） | 副歌行数 / 已知段落类型的演唱行数；另存分段标注行数 / 总行数 | 明确标注的段落中，多少演唱行属于副歌。仅有“副歌 × 2”而无可核实展开方式的文本标记待核 |
| duration_ms, tempo_bpm | 导入匹配录音的时长与节拍速度。若从可用音频提取 BPM，固定节拍检测方法，复核半速／倍速歧义 | 歌变长还是变短，节拍变快还是变慢 |
| energy, danceability, audio_valence（可选） | 读取同一来源、同一定义的录音级评分，保留来源。跨来源先验证可比性 | 听感强度、舞动感、声音正向感的分布；与歌词指标分别呈现 |
| arrangement_note（个案） | 从明确谈及该录音的制作署名或乐评记录具体配器、音色、段落变化，附证据链接；前奏长度可由核实的音频时间点相减 | 哪一段进入鼓机、合成器或吉他，有什么听觉作用 |

“悲伤相关词频”衡量措辞。若研究问题是“叙述者整体在表达什么情绪”，另设 context_emotion_label，先由能读原语的两人按统一标准标注完整歌词或段落，再验证分类器。可把它保留给精选曲目，前期不需要训练模型。乐评人的感受、歌词叙述者的感受、听众的实际感受应分别标明对象。

## 4. 多语言与汇总

1. 歌词保留原语，先按完整段落识别语言，短行结合相邻行复核。fastText 可给出候选；把最终语言、各语言明确行数、混合行数、待判行数分别记录。语言占比使用明确标注行数及其分母；标记纯器乐曲。听众市场和歌词语言是两个独立字段。[fastText 语言识别说明](https://fasttext.cc/docs/en/language-identification.html)
2. 主题在模型支持且验证过的语种中共用向量空间。按语言和年份分层抽样，请熟悉相应语言的读者盲评同主题跨语种歌曲和同语种不同主题歌曲，复核聚类是否只按语言或艺人分组；记录各语种样本量、人工一致率和典型误差。机器译文可用于读者释义或人工复核，记录其来源。
3. 情绪使用各语种的词典和分词器，如中文分词、日语形态分析。对混合歌词分段匹配，各段的命中数先相加，再除以相加后的有效词数。若只覆盖部分语段，记录语言与覆盖范围，部分结果单列。NRC 的多语种词表由英文自动翻译，应检查俚语、否定、反讽和歧义；对支持较弱的语言保留原榜记录和可用指标。不同语言的绝对词频默认分层阅读，跨市场可以选择共同语种再比较。[NRC EmoLex 翻译说明](https://saifmohammad.com/WebPages/NRC-Emotion-Lexicon.htm)
4. 重复率在保留全部演唱行的原文上计算。比较前检查各语言、各来源的分行习惯、副歌是否完整展开。同一组主题、情绪、重复指标可各有独立的可用状态。
5. 每个市场、年份、榜单类型单独汇总，默认每首歌等权。主题占比 = 该主题有效歌曲数 / 有主题结果的歌曲数；情绪和重复指标先算每首歌，再求组内均值或中位数。每图附“有效曲数 / 50”，并单列未获取、纯器乐、方法待验证。三年地区趋势默认筛选 19 个共同市场。2026 全球年内估计在同一时间轴标注截止日。年度歌单与同期累计榜分别统计。
