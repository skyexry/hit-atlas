# 热门歌曲小组分工用表

Excel 工作簿「歌曲与歌词.xlsx」包含下列各表和音频特征。歌词分析从歌曲母表取已选的 `lyrics_version_id`，用它读取版本来源与逐行原文。同一歌词版本分析一次。需要严格核验样本时，在「歌词匹配」筛选 `lyrics_status = 元数据匹配已确认`。年份和市场通过 `song_id` 连回榜位。

**特征提取的主输入是逐行歌词表。** 三张歌词表的用途，以及逐词、逐行和整首歌曲的分析结果存在哪里，见[歌词分析分工说明](../../docs/lyrics-analysis-notes.md)。

| 文件 | 一行代表 | 主键与用途 |
|---|---|---|
| [歌曲母表.csv](歌曲母表.csv) | 一个项目歌曲条目 | `song_id` 为主键。另存 `title`、`artist`、`spotify_id`、`duration_s`、`metadata_source`、默认 `lyrics_version_id` |
| [榜位对应.csv](榜位对应.csv) | 一个来源榜位 | 本批数据用 `source_file`、`year`、`market`、`position` 唯一定位。保留来源标题、署名、ID 和排名，按 `song_id` 连接母表 |
| [歌词匹配.csv](歌词匹配.csv) | 一个歌曲条目的歌词匹配结果 | 通过 `song_id` 连母表。记录选用的 `lyrics_version_id`、歌词核验状态 `lyrics_status`、匹配理由 `lyrics_match_rule` 和录音身份依据 `identity` |
| [歌曲元数据核验.csv](歌曲元数据核验.csv) | 一条歌曲的补查与来源记录 | 通过 `song_id` 连母表。分别记录艺人补查、Spotify ID 匹配，以及时长的取值来源与证据强度 |
| [歌词版本.csv](歌词版本.csv) | 一份固定的歌词转录 | `lyrics_version_id` 为主键，记录来源、来源曲名、艺人、专辑、时长、行数和文本摘要 |
| [逐行歌词.csv](逐行歌词.csv) | 一次实际出现的歌词行 | `line_id` 为主键，用 `lyrics_version_id` 连接版本。`line_no` 从 1 开始，重复副歌每次都有自己的行号 |
| [song_audio_features.csv](../音乐特征/song_audio_features.csv) | 一条已匹配的音频特征记录 | 按 `song_id` 连母表。字段口径和来源见[音乐性特征说明](../音乐特征/README.md) |

歌曲在各榜上出现多少次，可直接对榜位对应表按 `song_id` 计数。

## 歌曲身份与样本范围

基础表取自年度「榜单明细」和「地区同期Top50」。全球趋势表已包含在年度明细中。2026 保留原表统计窗口和年内估计标记。2024 加纳短榜按项目范围跳过。不同 Spotify ID 保留为不同目录条目，今后确认重复发行可建立别名映射。原始历史榜单缺艺人或 Spotify ID 的曲目保留原榜署名。母表的补配结果和来源记录在歌曲元数据核验表。缺少完整 ID 时，用规范化曲名与完整署名连接唯一目录候选，保留版本后缀。完整 ID 优先；21 位截短 ID 保存在榜位对应表的原始列。无可用 ID 或对应多个版本的记录以项目条目暂存，因此母表行数表示工作条目数。

地区同期榜按曲名和署名汇总。一行可代表多个目录版本；即使连到候选歌曲，该行的播放量仍属于原榜的汇总口径。2026 全球年内估计的代表录音也有相同限制。地区表的 chart_entries 表示上榜记录数；observed_days 表示市场观察窗口内的天数。计算某年或某地区的特征均值时，先确定唯一榜单口径，展示有歌词的榜位数及其占入选榜位数的比例。

## 本次歌词补查

歌词正文主要来自 LRCLIB 社区转录。补查时也采用艺人或发行方发布的逐行原文，以及歌ネット等歌词目录。每份歌词的实际链接保存在歌词版本表的 source_url。source_duration_s 和 source_album 保留歌词来源所载信息，来源缺值时留空。Spotify、Deezer 和 MGD+ 提供录音与署名核验依据。

已有默认歌词版本、正文和行号继续沿用。相同 Spotify ID 且时长同样吻合的曲目复用既有版本。两个目录条目的曲名、署名、发行版本和毫秒时长一致，且能找到同一份 LRCLIB 文本时，也可复用已有版本。新增歌词按来源记录编号、文本摘要和行序生成新行号。

新版本优先采用来源提供的纯文本。仅有时间同步歌词时按时间顺序取出正文，保留重复出现的歌词。新增匹配允许曲名中的大小写、部分标点、合作艺人附注与 remaster 后缀写法不同，保留 remix、现场、语言和 explicit 等版本限定。完整署名经过分隔符、顺序和少量已知中英文别名校正后匹配，独立时长差不超过 2 秒，且合格候选的用词序列一致时，标记为「元数据匹配已确认」。同一文本的不同标点、大小写或行切分，采用选定来源中的实际行序。官方原文与录音版本吻合，或两个歌词来源的正文一致且可用 LRCLIB 时长核对的记录，也归入「元数据匹配已确认」。正文精确度仍以听校为准。

已有的待复核版本沿用当时的选择。此次补查遇到多份转录时，在曲名和时长吻合、且有多数候选正文一致时暂用多数文本。其他冲突留待核实。部分合作署名省略、缺少可核验时长、历史榜依同名资料推定艺人的情况，也标为「候选歌词待复核」。歌词匹配表记录当前选用的版本和理由。正式歌词分析可以筛选「元数据匹配已确认」。

上一轮补入 66 个歌曲条目的逐行歌词，其中 26 个已核对、40 个为待复核候选。母表中共有 2,950 / 2,963 个歌曲条目可连接逐行歌词（99.6%）。其余 12 个标为「歌词暂缺」，1 个雨声音轨标为「无歌词」。 [12 首的来源和版本疑点](../../歌词核验依据/歌词缺项来源.csv)

2026 年 11 月 24 日，用更新后的独立录音时长与现有 LRCLIB 归档复核全部 1,474 条待复核记录。先比较曲名、完整艺人署名和独立时长，再比较相符候选经大小写、标点和换行归一化后的用词。核对保留重复词次，并以现有原文的 SHA-256 核实所选版本。231 条满足条件，歌词状态更新为「元数据匹配已确认」。其余 1,243 条保留候选状态，其中 839 条的合格候选存在用词差异。核对由规则执行，词句是否完整、是否与唱词逐字一致可进一步通过听校检查。 [全部复核记录](../../歌词核验依据/歌词再核对.csv) · [通过项的候选 ID、时长和校验值](../../歌词核验依据/歌词再核对证据.csv)

探索视图统一使用母表选好的默认歌词。已有多个合格转录时，优先采用支持记录最多的文本；榜位已有明确录音标识时使用该录音。区域榜按曲名和署名汇总的播放量保留原口径，歌词平台的候选支持数单独解释。严格核对的状态供做质量筛选和敏感性分析。全球 2024 和 2025 年分别有 48 和 47 个榜位可评分，叠加已核对条件后分别为 12 和 20 个。
