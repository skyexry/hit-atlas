# 热门歌曲小组分工用表

Excel 工作簿「歌曲与歌词.xlsx」收录以下四张表。使用 CSV 时，先打开「歌曲母表.csv」，以 song_id 分工。要开展歌词分析，筛选 lyrics_status 为「元数据匹配已确认」，按 lyrics_version_id 连接「逐行歌词.csv」。同一歌词版本只计算一次；回到年份或地区视图时，再通过「榜位对应.csv」按 song_id 找到榜位。历史转载、原榜扩展、主样本及同期日榜各有自己的范围，须按分析目的筛选。

| 文件 | 一行代表 | 主要用途 |
|---|---|---|
| 歌曲母表.csv | 一个项目歌曲条目，含待核录音 | song_id 为项目键。title、artist 为展示字段；spotify_id、duration_s、metadata_source 记录目录编号及独立时长依据。chart_rows 为对应的原始榜位条数 |
| 榜位对应.csv | 一个来源榜位 | source_file、year、market、position 共同定位本批输入中的一行。保留原始曲名、署名、ID 和排名。recording_link_status 标记榜位关联依据 |
| 歌词版本.csv | 一份冻结的 LRCLIB 歌词转录 | 来源页面、曲名、艺人、专辑、时长、行数及清理后文本 SHA-256，可用于复核 |
| 逐行歌词.csv | 歌词中一次实际出现的非空文本行 | line_no 从 1 开始，重复副歌按每次出现保留。line_id 在本版本内固定。小组的逐词指标可再加 token_index 记录词在行内的位置 |

## 歌曲身份与样本范围

基础表取自年度「榜单明细」和「地区同期Top50」。全球趋势表已包含在年度明细中。2026 保留原表统计窗口和年内估计标记。2024 加纳短榜按项目范围跳过。不同 Spotify ID 保留为不同目录条目，今后确认重复发行可建立别名映射。artist 缺失且无可用 ID 的历史记录独立占位。缺少完整 ID 时，用规范化曲名与完整署名连接唯一目录候选，保留版本后缀。完整 ID 优先；21 位截短 ID 保存在榜位对应表的原始列。无可用 ID 或对应多个版本的记录以项目条目暂存，因此母表行数表示工作条目数。

地区同期榜按曲名和署名汇总。一行可代表多个目录版本；即使连到候选歌曲，该行的播放量仍属于原榜的汇总口径。2026 全球年内估计的代表录音也有相同限制。地区表的 chart_entries 表示上榜记录数；observed_days 表示市场观察窗口内的天数。计算某年或某地区的特征均值时，先确定唯一榜单口径，展示有歌词的榜位数及其占入选榜位数的比例。

## 歌词匹配和行号

录音时长依据记录在每首歌的 metadata_source。可用来源包括 Spotify 曲目页或歌单、MGD+、既有榜单数据文件和 Deezer 目录。同期周榜曲名和署名唯一匹配得到的 Spotify ID 在 identity 列单独标记。Deezer 以标题与首位艺人检索，候选时长与显式内容标记各须一致，属于跨平台旁证。

按曲名和艺人检索 LRCLIB，在返回的候选中核对完整标题、署名和录音时长（容差 2 秒）。统一大小写、Unicode、空白和署名分隔符。保留有文本的候选，去掉空行和整行方括号段落标签，保留原文、顺序、标点与重复行。所有通过条件的候选归一后仅有一种文本，才签发 lyrics_version_id。如有多个相同文本来源，选择时长最近者，再按来源 ID 排序。版本键包含来源 ID 和文本摘要；任何正文变化均生成新版本。line_id 由版本键和行序组成。

「元数据匹配已确认」是对来源与冻结转录的自动核验，歌词来源是社区转录，逐字听校、译文辨识、clean／explicit 用词差异仍需人工复核。展示词级情绪证据前，适合优先听校对结论有影响的行。状态为「多个文本待判定」「未取得严格匹配」「缺独立录音时长」或「查询未取得响应」时保留歌曲，歌词字段留空。缺歌词代表缺测，计算指标时单列覆盖率。
